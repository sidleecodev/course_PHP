另一份確認：

```php
use Illuminate\Database\Eloquent\Relations\BelongsTo;
```

```php
// 大事記
class MileStone extends Model
{
    public $timestamps = false;
    protected $table = "milestone";
    protected $primaryKey = 'id';
    protected $fillable = ["id", "typeId", "years", "months", "title", "content", "createTime"];

    public function types(): BelongsTo
    {
        // typeId：milestone資料表的外來鍵
        // id：milestone_type的主鍵
        // 等同於 SELECT a.*, b.* FROM milestone a INNER JOIN milestone_type b ON a.typeId = b.id
        /*
        也可以用(DB要use Illuminate\Support\Facades\DB)
          DB::table("milestone as a")->selectRaw("a.*, b.*")->join("milestone_type as b")->get()
        或
          DB::table("milestone as a")->join("milestone_type as b")->selectRaw("a.*, b.*")->get()
        順序不影響
        DB：資料庫  table：資料表   join：inner join兩邊都有資料    selectRaw：查詢欄位 get：取全部資料
        selectRaw("a.*, b.*")也可以改用select("a.*", "b.*")
        */
        return $this->belongsTo(MileStoneType::class, "typeId", "id");
    }
}
```

> 原碼的 JOIN 註解保留。關聯不是立即執行 INNER JOIN；兩個 DB 範例缺少 join 的 ON 欄位條件，不能直接當完整可用程式。這裡不額外展開新查詢技巧。

### 6-2. doDelete

老師筆記放在 layout.blade.php。依原指示搜尋 jQuery CDN，選 4.0 minified；確認套件載入，若已在 layout 引入就不重複載入：

```html

```

```blade
<script>
    // 傳入被點擊的按鈕，刪除成功後移除它所在的資料列
    function doDelete(id, btn) {
        Swal.fire({
            icon: "question",
            title: "確定刪除？",
            showDenyButton: true,
            showCancelButton: false,
            confirmButtonText: "確定",
            denyButtonText: "放棄"
        }).then((result) => {
            if (result.isConfirmed){
                // 使用ajax是為了讓資料送到後端執行
                $.ajax({
                    // 送去哪裡
                    url: "/admin/milestone/types/delete",
                    type: "post",
                    data: {
                        // 傳給後端的資料
                        id: id,
                        _token: "{{ csrf_token() }}"
                    },
                    // msg是接住後端回傳的內容
                    success: function(msg){
                        Swal.fire("已刪除!", "", "success");
                        /* btn: 傳進來的button
                           closest: 尋找最近符合條件的元素
                           tr: 表格中的列
                           [data-row]: 具有data-row屬性
                           tr[data-row]: 從目前元素(button)開始，往上尋找最近的一個符合條件的<tr>
                           remove()只會從畫面上移除這列，不會移除資料庫的，資料庫那邊要交由controller移除
                            */
                        // 整句意思：從按鈕往上，找到最近一個帶有 data-row 這個 HTML 屬性的 <tr>，並從畫面上移除
                        $(btn).closest("tr[data-row]").remove();
                    }
                });
            }
        });
    }
</script>
```

### 6-3. Controller 真正刪除

```php
public function delete(Request $req){
MileStoneType::destroy($req->id);
    }
```

| 位置 | 本例負責什麼 |
| --- | --- |
| onclick 的 this | 傳入被點擊的按鈕元素，不是 class="btn" |
| data 的 id | 將編號放在 POST 請求內容，路由因此不必含 {id} |
| destroy | 刪除資料庫紀錄 |
| closest／remove | 找按鈕所在的 tr[data-row]，移除目前畫面的一列 |

原文把 this 說成「指定 id」不夠精準，應是傳入按鈕元素。success 只是成功收到回應，這份程式未檢查 msg 的業務結果；delete() 也沒有明確回傳成功內容。刪除確認應用未被事件引用的練習類別，不用既有關聯資料驗收刪除。

```php
class CheckManager
{
    public function handle(Request $request, Closure $next): Response
    {
        if(empty(session()->get("userId"))){
            return redirect("/admin");
        }
        return $next($request);
    }
}
```

| 寫法 | 原筆記說明 |
| --- | --- |
| Request $request | 接收目前 HTTP 請求，$request 代表使用者送來的請求 |
| Closure $next | 接收可讓請求繼續往下執行的函式 |
| : Response | 宣告方法回傳 Response 類型的結果 |
| $next($request) | 檢查通過後，交給下一個處理階段 |
| Session 沒有 userId | 回應 redirect("/admin")，不繼續後面的路由功能 |
